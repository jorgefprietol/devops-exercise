EJECUTAR Y EVALUAR LOCALMENTE
Con Docker Linux iniciado y Python 3.10 o posterior, desde el repositorio:
py -3 scripts/demo.py

Para verificar también Kubernetes con dos trabajadores, tres entornos y HPA:
py -3 scripts/lab.py --all-environments
py -3 scripts/verify_environments.py

En Linux/macOS: python3 en lugar de py -3. La primera descarga requiere
Internet. No se necesita una URL pública ni depender del equipo del autor.
Postman: importar la colección y el entorno privado que genera el arranque;
seleccionarlo como activo. Instrucciones completas en postman/README.md.

CONTENIDO Y COMPROBACIONES
- API .NET, Kong, Redis, Docker y manifiestos Kubernetes versionados.
- Compilación, pruebas, imagen por digest y despliegue en GitHub Actions.
- master -> production; develop -> development; etiquetas -> staging.
- Ejecución manual y selección de una versión publicada.
- 43 pruebas .NET; 18 pruebas Python; umbral de cobertura de líneas del 80 %.
- Análisis estático, formato y auditoría de dependencias bloqueadas.
- Dos trabajadores con réplicas distribuidas; HPA de 2 a 6 pods de la API.
- JWT único por transacción y rechazo de repeticiones entre réplicas.
- Evidencia de ciclos TDD concretos en evidence/tdd-seguridad.json y
  evidence/tdd-portabilidad.json; no se afirma TDD retrospectivo de todo el código.

La matriz REQUISITOS.csv indica implementación, comprobación y alcance.
Los informes de pruebas y cobertura se descargan desde GitHub Actions.
El despliegue se comprueba mediante una conexión local autenticada a Kubernetes,
sin túnel público. El pipeline del propietario requiere su agente encendido.

PORTABILIDAD Y LÍMITES
Docker funciona en equipos compatibles con contenedores Linux. NUBE.md y
scripts/deploy_cluster.py permiten preparar la aplicación para un cluster
existente, con perfiles EKS/AKS. No se han creado ni probado recursos cloud.
Los nodos kind comparten un PC; Redis tiene una sola réplica persistente.
production es el entorno lógico de la evaluación, no un servicio con SLA.
La API implementa la respuesta solicitada; no hay una cola de entrega real.

HTTP
GET, PUT, PATCH, DELETE, OPTIONS y TRACE: 405 y cuerpo ERROR.
HEAD: 405 sin cuerpo, conforme al protocolo HTTP.
Para una demostración pública opcional existe --public; no es necesario para
la evaluación local. Las URLs Pinggy gratuitas duran hasta 60 minutos.
